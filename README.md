# Лабораторная работа №64 — битонная сортировка

Две готовые реализации на ANSI C89, реальный компонент Eco ACOM и параллельный
исполнитель на pthread. Варианты получены локальной Qwen с кратким и подробным
промптами. В репозитории находятся исходники, независимые проверки, измерения
и один сравнительный отчёт.

## Состав

- `solutions/short-1/` — проверенная реализация краткого варианта.
- `solutions/detailed-1/` — проверенная реализация подробного варианта.
- В каждом проекте: `SourceFiles`, `HeaderFiles`, `SharedFiles`,
  `UnitTestFiles/SourceFiles` и `UnitTestFiles/HeaderFiles`. Здесь есть алгоритм,
  компонент, фабрика, публичные интерфейсы, консольный клиент и пул потоков.
- `reports/Lab 64 Bitonic Sort.docx` — приложенный пользователем отчёт,
  скопированный без изменений.
- `checks/reference-public.c` — независимый клиент для итогового публичного API;
  `checks/reference.c` и остальные проверки — исходные материалы эксперимента.
- `verification/` — сохранённые результаты проверок и сравнения с `qsort`.
- `measurements/`, `benchmarks-comparison.csv` — исходные замеры и сводные данные.
- `figures/` — схема сети и график производительности.
- `short.txt`, `detailed.txt`, `task.md` — промпты и исходная постановка.
- `runs/experiment-20261007-153303-5cad0ff0/` — данные всех шести попыток,
  включая четыре неуспешные; в `workspace` сохранены их последние исходники.
- `seed/Eco.Lab64/` — общий незавершённый каркас до генерации.
- `rejected/short-2-request25/`, `revisions/` — отклонённая промежуточная
  реализация и её результаты. Она не является рабочим решением.
- `provenance/export.json`, `SHA256SUMS` — происхождение файлов и контрольные суммы.

## Сборка и запуск на macOS Apple Silicon

Нужны Python 3.9 или новее, Apple Command Line Tools и отдельно полученный
архив SDK `Eco.Framework_20260918.zip`. Проверка инструментов:

```bash
python3 --version
xcrun --find clang
```

Если `clang` отсутствует, выполните `xcode-select --install`, завершите системную
установку и повторите проверку. Команды ниже выполняются из корня этого репозитория.

Подключите SDK из папки `~/Downloads/Design operating systems`:

```bash
python3 scripts/lab.py setup
```

Для другого расположения архива:

```bash
python3 scripts/lab.py setup --archive "/absolute/path/Eco.Framework_20260918.zip"
```

Скрипт проверяет SHA256 поставки и извлекает необходимые заголовки и библиотеки
macOS arm64 в локальную `.eco/Eco.Framework`. SDK исключён из Git и подключается
из отдельной поставки. Для сборки готового проекта `eco-wizard` не требуется.

Запустите оба консольных примера:

```bash
python3 scripts/lab.py demo
```

Ожидается `status=0` и массив `-7,-3,0,1,1,8,9`. Фабрика регистрируется в
`IEcoInterfaceBus1`, клиент входит через `EcoMain`, сортировка использует
публичный `IEcoSortAndSearch` и четыре настоящих рабочих потока.

Проверьте оба варианта:

```bash
python3 scripts/lab.py test
```

Для каждого ожидается `SUMMARY,cases=1664,failures=0`, затем успешное прохождение
21 сценария ACOM (145 дополнительных проверок). Для проверки только ACOM есть
команда `python3 scripts/lab.py com-test`. Сборка использует
`-std=c89 -pedantic-errors -O2`, UBSan и проверку зависимостей компонента через
`nm`. Независимые тесты сверяют реальные результаты с `qsort`, проверяют разные
типы, произвольные длины, сохранение данных, ошибки и параллельное исполнение.
Прохождение тестов не является формальным доказательством корректности.

Можно выбрать один вариант:

```bash
python3 scripts/lab.py demo --variant short
python3 scripts/lab.py test --variant detailed
```

Для уже подготовленного SDK вместо `setup` передайте путь к корню `Eco.Framework`:

```bash
python3 scripts/lab.py test --framework "/absolute/path/Eco.Framework"
```

Все новые исполняемые файлы, библиотеки и журналы сохраняются в
`solutions/<вариант>/BuildFiles/Standalone/<команда>/`, которые исключены из Git.
Сохранённые результаты лабораторной при повторных проверках не перезаписываются.

## Повторный замер производительности

Освободите компьютер от тяжёлой фоновой нагрузки и запустите:

```bash
python3 scripts/lab.py benchmark
```

Клиент измеряет `CLOCK_MONOTONIC` wall время при `-O2` без UBSan: последовательная
сортировка, четыре потока и `qsort`; четыре размера, четыре вида входов, один
прогрев и семь замеров каждого случая. Для каждого варианта получается
336 замеров, которые сверяются с эталоном. Новые CSV находятся в
`solutions/<вариант>/BuildFiles/Standalone/benchmark/timings.csv`.
Исторические 672 замера в `measurements/timings.csv` сохраняются отдельно.

## Интерфейс и ограничения

`SharedFiles/IEcoSortAndSearch.h` объявляет универсальный метод
`Sort(base, count, width, compare)` по смыслу `qsort`. `Configure` задаёт число
работников и синхронного исполнителя, `GetResult` возвращает статус и статистику.
Базовый `IEcoLab64` содержит расширенный контракт сортировки.

Контракт: длина до 1 048 576, размер записи больше нуля, произведение длины и
размера помещается в `uint32_t`; 1–16 работников. Для нескольких работников
нужен исполнитель. Компаратор задаёт полный порядок и допускает одновременные
вызовы. Массив принадлежит клиенту; стабильность сортировки не гарантируется.
Компонент выделяет память через Eco allocator; pthread и libc используются
только клиентом и независимыми проверками.

`SourceFiles/BitonicMethods.c` в двух рабочих проектах совпадает с полученными
от модели реализациями. Общие фабрика, управление временем жизни, публичный
адаптер `SortFacade.c` и исполнитель поставляются отдельно от алгоритма.
SHA256 алгоритмов приведены в `solutions/manifest.json`.

## Результат сравнения промптов

Проведены три пары. У каждого подхода один успешный результат из трёх;
четыре провала сохранены в стоимости эксперимента. Ни одна исходная попытка
не завершилась успешно в первоначальном бюджете без дополнительных уточнений.

| Успешный вариант | Активное время, мин | Входные токены | Выходные токены | HTTP запросы | Уточнения |
|---|---:|---:|---:|---:|---:|
| Краткий, повтор 1 | 27,65 | 315 735 | 28 365 | 20 | 7 |
| Подробный, повтор 1 | 20,87 | 286 860 | 23 272 | 23 | 11 |

За всю серию выполнено 137 HTTP запросов, израсходовано 1 852 802 токена.
Сравнение успешной пары не доказывает общего превосходства подробного промпта:
надёжность в серии одинакова, уточнения были адаптивными, история сокращалась.
Полный вывод и ограничения находятся в приложенном отчёте и `conclusion-final.txt`.

## Сохранность и границы архива

Исходные алгоритмы и приложенный отчёт скопированы побайтно. Каркас рабочих
компонентов позднее исправлен; подробности и проверка приведены в `COM-FIX.md`.
Word отчёт и сохранённые замеры относятся к исторической версии до исправления.
В JSON журналах тела
сообщений запроса заменены ролью, длиной и SHA256: исходный системный контекст
содержал закрытый заголовок SDK. Числовые метрики, `usage`, параметры запросов,
ответы модели, уточнения и диагностика сохранены. `provenance/export.json`
различает неизменные копии и такие экспортированные журналы и содержит SHA256
оригиналов. Полные журналы с закрытым контекстом остаются в исходном эксперименте.

Абсолютные пути в исторических диагностических файлах отражают исходный запуск;
они не используются командами сборки этого репозитория. `task.md` фиксирует
первоначальный план; фактические статусы и замеры — в `runs` и `measurements`.

Проверить контрольные суммы переданных файлов:

```bash
shasum -a 256 -c SHA256SUMS
```

Окружение солвера, MLX, модель, виртуальное окружение Python, закрытый SDK,
старые отчёты и готовые бинарные файлы в архив не включены. Скрипты используют
только стандартную библиотеку Python и служат для сборки готовой лабораторной.
